# 课程题库语义答疑

把 496 道自然辩证法题库做成一个能用**大白话提问**的检索系统，并配套一套可复现的评测。

核心问题不是"能不能检索到"，而是**"学生用口语问，系统还能不能找对"**。

---

## 结果

150 条测试用例（50 道题 × 2–3 种学生口语问法），指标为 hit@1（第一位就是正确题目）：

| 方案 | hit@1 | hit@3 |
|---|---|---|
| 纯向量检索（基线） | 46.7% | 74.0% |
| 口语 → 书面改写 | 43.3% | 70.7% |
| 关键词/术语扩展 | 24.0% | 56.0% |
| 纯 BM25 | 53.3% | 72.7% |
| 向量 0.5 + BM25 0.5 | 58.0% | 79.3% |
| **+ 解析入索引（最终）** | **58.7%** | **82.0%** |

随机基线 hit@1 = 0.20%。

**最终：hit@1 从 46.7% 提升到 58.7%（相对 +26%），hit@3 从 74.0% 提升到 82.0%。**

上表是**检索命中率**（正确答案有没有排进前 k），不等于"答对了"。
另抽 10 条跑完整流程做了生成质量检查：**回答正确 10/10，硬答 0 条**，题库外的问题能正确拒答。

再往上做了一层 Agent（多步工具调用），另建 17 条评测：**17/17，连跑两轮一致**，平均每条 1.4 次工具调用、4.6 秒。
详见下方「从检索到 Agent」。

## 三个发现

**1. 让查询"更像文档"是无效的，甚至有害。**

用大模型把"四大发明是哪四个来着"改写成"中国古代四大发明的具体内容是什么"，hit@1 反而降了 3.3 个点。
原因是改写只做了语气正式化（啥→什么），而检索的鸿沟在词汇对齐（最牛→高峰）。
更进一步，把问题扩展成 12 个同义术语后，hit@1 暴跌到 24.0%——
**向量是加权平均，堆泛化词会把查询拉向整门课的"质心"，离具体那道题更远。**

**2. 纯 BM25 的 top-1 精度高于向量检索（53.3% vs 46.7%），但召回广度更低（hit@3 72.7% vs 74.0%）。**

两者错在不同的地方：BM25 认词，向量认意思。所以融合有效——**互补的前提是"错得不一样"**。

**3. 按"题目 ID"打分是坏指标。**

题库里有大量"考同一知识点但表述不同"的题（判断题改写选择题、同一句挖不同的空）。
按 ID 打分会把这类"答对了"判成"答错了"，严格口径与等价口径相差 21 个点。
**这也是为什么评测集不能拿被测系统的输出反推**——等价标注一旦参考了基线结果，就会反过来偏袒基线。

## 管线

```
题库 docx ──解析──▶ 496 题结构化 JSON（答案由字母还原成内容）
                        │
                        ├──▶ bge-small-zh-v1.5 编码 ──▶ vectors.npy (496×512)
                        └──▶ jieba 分词 + BM25 倒排
                                        │
学生口语提问 ──┬──▶ 向量相似度 ──┐
               └──▶ BM25 分数 ───┴─▶ min-max 归一化后 0.5/0.5 加权 ──▶ top-k
```

## 运行

环境：Python 3.11 + PyTorch（CPU 即可），无需显卡。

```bash
# 1. 解析题库
python scripts/parse_questions.py

# 2. 建索引（首次会下载 embedding 模型，约 100MB）
python scripts/build_index.py

# 3. 跑一遍基线
python scripts/run_eval.py

# 4. 随便问
python scripts/ask.py

# 5. Agent 对话（模型自己决定查什么）
python scripts/agent.py

# 6. Agent 评测
python scripts/eval_agent.py
```

依赖：`torch` `transformers==4.46.3` `jieba` `numpy` `openpyxl` `scikit-learn`

> 国内注意：`transformers` 需锁 `4.46.3`（5.x 要求 torch≥2.6）；HF 官网不通，代码里已设 `HF_ENDPOINT=https://hf-mirror.com`。
> Windows 上若报 OpenMP 冲突，设环境变量 `KMP_DUPLICATE_LIB_OK=TRUE`。

## 局限

- 测试集由大模型起草后人工校订，**比真实学生提问更"懂事"**，因此基线可能偏乐观
- 等价组只标注了基线 top-3 范围内的候选，覆盖不全
- 未做 Rerank 精排（CPU 上较慢），这是最对症的下一步
- 只验证了单一课程语料，规模 496 题，不能代表更大题库的表现
- Agent 评测 17 条已全部通过，**不再有区分度**；且语义类答案靠词表判分判不干净（详见下文）

## 加生成之后（`ask.py`）

默认流程：混合检索 top-3 → 把题目、答案、**解析**交给大模型 → 口语回答，**答不出就拒答**。
加 `--no-gen` 只做检索，用来单独观察检索环节。

**为什么要加拒答**：检索永远会返回 top-3，哪怕库里根本没有相关内容。直接把错题喂给模型，它会照着编出一段通顺但完全错误的回答——这比答不出来危险得多。

**为什么不用相似度阈值做拒答**：实测过（`probe_threshold.py`），不行。

| 查询类型 | top-1 向量相似度 |
|---|---|
| 检索命中的 | 0.527 ~ 0.787 |
| 检索**没**命中的 | 0.505 ~ 0.788 |
| 完全无关（红烧肉、天气） | 0.458 ~ 0.533 |

命中和没命中的分布**完全重叠**——相似度高不代表检索对了。所以改用让模型判断相关性，实测有效：

- 「那个系统有啥特点」→ 正确答出"开放性、动态性、整体性、层次性"
- 「红烧肉怎么做才好吃」→ 输出"题库里没有找到"

**暴露出的真问题（已解决）**：旧的题库只有"答案是什么"，171 道判断题的答案是两个字——正确/错误，知识藏在题干里。
「自然辩证法都研究哪些内容」检索到了三道正相关的判断题，模型仍拒答，因为三道的答案都是"错误"（各自漏掉一项），语料里从未给出完整答案。**模型拒绝猜，这是对的。**

换成带解析的题库后（`questions_v2.json`，496 题、1.7 万字解析），同一个问题回答正确：

> 自然辩证法主要研究自然观、科技观（史）、科学认识方法论、科技与社会这几块内容。注意别漏掉"自然观"或"科学认识方法论"，少了就不完整。

> 这条比任何技巧都重要：**RAG 的效果上限由语料决定，不由模型决定。** 检索侧换模型、调参数，都不如补一份带解析的语料管用。

## 从检索到 Agent（`agent.py`）

检索回答的是"哪几条最像这句话"。「哪几讲提到盖伦」「一共几道提到第谷」「判断题里有几道答案是错的」这些问题问的是**覆盖和计数**，相似度再高也算不出来——`ask.py` 遇到它们只能拒答。

所以加了一层 Agent：模型每一步自己决定调哪个工具，看到结果再决定下一步，够了才回答。

| 工具 | 作用 |
|---|---|
| `search` | 向量 + BM25 混合检索 top-k，用于"不确定有没有相关内容" |
| `detail` | 按题号取完整题干、选项、答案、解析 |
| `stats` | 按讲次 / 题型 / 答案统计，返回数量与分布 |
| `grep` | 全库逐题扫关键词，返回总数、讲次分布、每道题明细 |

**三个终止条件**，缺一不可：模型输出 `final` / 步数上限 8 / 同一工具加同样参数重复调用（检测原地打转）。

第三个是最容易被忽略的。做 AI 编程助手实验时见过模型反复生成同样文件停不下来，根因就是没有收敛判断——步数上限只能兜底，重复检测才是真正的闸门。

不用 LangChain 的理由：这个循环不到 60 行，写成自己的，才能回答"终止条件怎么定""模型打转怎么办"。套框架的人答不上来。

### 评测：17 条，17/17

单独一套，和检索那 150 条不通用（那些测的是"有没有命中那道题"）。分五类：覆盖 4、统计 6、问细节 4、集合运算 2、拒答 1。

平均 **1.4 次工具调用、4.6 秒/条**。这个数比改之前低——加了工具、加了步数，调用次数反而下降，因为工具对了就不需要反复试错。

### 三条失败，三种修法

**① 覆盖类答错：「哪几讲提到盖伦」答"只有第二讲"，真值是两讲共 3 道。**

它自己的检索结果里就摆着第四讲那两道，没看见。根因是 `search` 返回 top-k，模型把这 5 条当成了全集。→ 加 `grep`，返回 total 和全部命中。

**② 数不出来：「判断题里有几道答案是错的」拒答"工具没法按答案筛选"。**

加了 `answer` 维度后一次调用得出 87 道。改之前它用 `detail` 逐题读，8 步只核对了 5 道就耗尽预算，交了一份"给不出准确总数"的半成品。

**③ 数字差 1：判断题答案=错误，按字符串筛是 86，实际是 87。**

题库有 1 道（`judge-第四讲-8`）的答案写成"否"而不是"错误"。这种错最麻烦——不报错，只是少 1 道。→ 归一化（否/错/×/F → 错误）。

### 判分器自己也要被验证

这轮最值钱的教训不是系统哪里错了，是**评测本身错了两次**：

- 第一版跑出 10/10，其实第 9 条是假的：标准答案被我写成"哥白尼"（实为地心说），而判分只做了 `in` 判断，把"未接受哥白尼"判成命中。标准答案错 + 断言太宽，两者合谋给出了漂亮的假分数。
- 「盖伦和牛顿是否同讲」试了三种判法：禁止提其他讲次（误杀）、要求出现"唯一/重合"（换个说法就误杀）、最后只查有没有说"第四讲"（松了，但不再误杀）。

现在 `eval_agent.py` 里有两道前置校验，任何一道不过就直接退出：

1. `selftest()`：19 个已知对错的样本先验证判分逻辑
2. `raw_scan()`：标准答案写死在脚本里，启动时用独立扫描核对一遍，防"代码改了、标准答案跟着漂"

> **评测集的作用不是给出一个好看的数字，是持续找出下一个洞。** 每补一个洞分数就回到 100%，然后再加更难的题。17/17 现在不再有区分度——这句话本身就该写进来。
